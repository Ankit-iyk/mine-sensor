# SUBSENSE data and benchmark datasheet

## Scope and provenance

The repository contains a CSV called `sensor_data.csv` and an event log, but `docs/evaluation/placeholder_data/README.md` classifies the bundled files as synthetic placeholders. The available CSV coverage was audited as 38,700 rows at nominal 0.1-second intervals (about 64.5 minutes); this is not a two-hour real-world recording. Its event log documents scripted events. No physical sensor recordings are available. Evaluation scenarios generated by `ai_engine/evaluation/datasets.py` are a separate, explicitly simulated dataset and are not merged into those CSV files.

## Generation and labels

The evaluation generator uses a fixed 3-node topology, 180 steps per node, seeded scenario construction, and scripted event onset/labels. Its scenario matrix includes normal, tilt changes, vibration/acceleration disturbances, correlated drift, dropout, jitter, nuisance impulses, phone-like vibration, and mixed cases. See `docs/evaluation/PROTOCOL.md` and `docs/evaluation/SIMULATOR_PARAMETERS.md` for seeds, splits, assumptions, and event semantics. Labels describe the code-generated condition, not mine instability.

## Sampling, missingness, and transforms

Nominal evaluation intervals are 1 second with a separate shifted/jittered condition. Sensor dropout is represented by omitted rows and recovery metadata, not imputed readings. Current compared feature detectors do not implement packet freshness/outage detection; that case is marked unsupported. Evaluation feature rows pass through backend filtering and rolling feature extraction. The separate placeholder CSV uses its own nominal interval and must not be combined with the evaluation benchmark without provenance.

## Consent, privacy, and access

The inspected benchmark is synthetic and contains no known physical participant data. This is a code and repository inspection, not a formal privacy audit. Before external release, inspect all repository artifacts for secrets and unrelated personal data. No claim is made that all possible metadata or credentials have been independently audited.

## Known limitations

Simulation assumptions are not calibrated to official sensor specifications or mine measurements. Scripted events, short duration, assumed cross-node dependence, simplified noise, and limited missing-data behavior constrain conclusions. The repeated nuisance-control metric caveat is documented in `docs/evaluation/CONFIRMATORY_ANALYSIS.md`. Use only for reproducibility of the specified software benchmark, not real-world performance claims.
