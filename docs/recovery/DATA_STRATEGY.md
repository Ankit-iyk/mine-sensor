# Stage 0 data strategy

This is a source inventory and a generator design, not a new evaluation. In
Phase 2, the Mount Erzberg README, blast metadata, and full SEG-Y file were
downloaded to a temporary directory, decoded, and inspected; the Jacobina
reproducibility archive was also downloaded and its file listing,
`LICENSE.md`, and `DATA_AVAILABILITY.md` were inspected. None of these files
was added to the repository. Dataset observations below are source-data
descriptions, not recordings from this project's node, and do not calibrate
its sensors.

## Proposed physically grounded simulated generator

The current benchmark and demo simulator are too coarse to model the target
distinction. The implementation points are `simulator/simulator/node.py:109-138`,
`simulator/simulator/scenarios.py`, `ai_engine/evaluation/datasets.py:51-58,
114-196, 217-296`, `backend/app/processing/features.py:83-131`, and
`backend/app/intelligence/temporal.py:82-91`. The v1 generator and frozen
artifacts must remain unchanged; implement the generator in a separately
versioned v2 module.

### Blast impulse class

The public Mount Erzberg particle-velocity records are used only as context
for plausible blast duration and frequency ranges. They are not used to fit
the v2 generator or calibrate this node, and their mm/s values are not mapped
to the node's acceleration or normalized vibration units. Sensor response,
mounting, and cross-device calibration are unverified. A parametric generator
is a controlled simulation, not a fit to node data:

`v_j(t) = sum_k A[j,k] * exp(-(t - t0 - d[k]) / tau[j,k]) * sin(2*pi*f[j,k]*(t - t0 - d[k]) + phi[j,k])`

for `t >= t0 + d[k]`, and zero before each pulse. This equation is a model
assumption; its parameter distributions must be fit from the source records,
not selected to make a detector look good.

| Parameter | Proposed setting | Basis and limitation |
|---|---|---|
| Source sample rate and trace length | 500 Hz; 5-second traces (2,500 samples) | Directly documented in the README and verified in all downloaded trace headers. This is the source recording resolution and trace duration, not a verified node rate or measured blast-event duration. |
| Number of source axes | Three components | Directly documented for the source array. Preserve component orientation/metadata; no axis remapping to the node without mounting information. |
| Blast onset `t0` | Align to the trace's documented/inverted time zero; retain any uncertainty | The source README says absolute shot times were unavailable and time zero was inverted from the recorded data. Onset uncertainty must remain explicit. |
| Sub-shot delays `d[k]` and charge metadata | Read each event's recorded delay and charge from `BLASTS.txt`; do not infer a linear charge-to-amplitude law | These values are provided as blast metadata. Non-electric delay times are documented as having millisecond-scale errors; some records have overlapping follow-up blasts. |
| Source particle-velocity peaks | Absolute sample values in the downloaded file range from 0.0098526124 to 76.2965698242 mm/s; absolute-value 50th, 90th, 99th, and 99.9th percentiles are 0.0098526124, 0.1367233992, 1.0125990295, and 4.5081396503 mm/s | Directly computed from 14,451 decoded traces. This observed source range may describe the public source records only; it cannot set the normalized peak-amplitude range for this node because units and sensor response differ. |
| Simulated node pulse amplitude `A[j,k]` | Keep as a separately declared assumption; do not map the public mm/s peaks to node acceleration or vibration values | Sensor response, mounting, and cross-device calibration are unavailable. The v2 protocol's normalized amplitude values remain assumptions and are not data-derived. |
| Dominant frequency `f[j,k]`, phase `phi[j,k]`, and decay constant `tau[j,k]` | The v2 protocol's frequency and decay ranges remain explicitly labeled assumptions; no source-to-node fitting is used | Public source records provide context for plausible source frequency and duration scales only. The damped-sinusoid form and the v2 parameter ranges are not calibrated to the node or inferred as measured parameters. |
| Source trace duration | 5 seconds per trace, 2,500 samples at 500 Hz | Verified in downloaded trace headers and documented in the source README. It is the stored record window, not a measured blast-event duration. |
| Source event duration / decay range | Not derived in this inspection; source records include inverted time zero, overlapping follow-up blasts for two production records, and no absolute shot times | Do not call trace length an event duration. A trace-level duration estimator would need a predeclared envelope/onset rule and careful treatment of overlapping shots. The frozen v2 decay grid remains an assumption. |
| Particle velocity to node acceleration conversion | No conversion until MPU6050/SW-420 signal paths and mounting are calibrated; if a calibrated response exists, document filtering, differentiation, units, and resampling | The source release states its data were time-integrated and converted to particle velocity in mm/s. Differentiating without response/noise control would not establish actual node acceleration. |
| Transient tilt artifact `delta_theta_b` | Peak magnitude 0 to 0.10 degrees, followed by recovery; **assumption only** | Satisfies the requested small, transient apparent-tilt behavior for simulation. No supplied blast record measures tilt at this node, so neither the bound nor its distribution is empirically calibrated. |
| Tilt recovery time `tau_theta` | 1 to 10 seconds; **assumption only** | A provisional recovery range to test, not a measured property of the sensor, mount, or mine. Replace only with sourced or bench-measured evidence. |
| Background sensor noise | Keep the current source constants, tilt sigma 0.05 degrees and acceleration sigma 0.02 m/s^2, only as explicitly named simulator assumptions until measured | Values are in `simulator/simulator/node.py:32-33`; they are not datasheet- or bench-calibrated. Freeze them before v2 runs and include a predeclared sensitivity grid. |
| Other-transient nuisance amplitude and recovery | Derive from labeled bench/field disturbance recordings when available. Until then, publish only a sensitivity grid whose levels are explicitly called assumptions; do not call them blast measurements. | No suitable labeled node recordings were found in this repo. A guessed single nuisance waveform would not establish nuisance rejection. |

### Progressive-tilt / subsidence-proxy class

Generate a monotonic angle trajectory, not a one-off step:

`theta(t) = theta0 + integral(from t0 to t) r(u) du`

with `r(u) >= 0` after onset and no return to baseline during the episode.
For a simple initial version, ramp the slope from zero to `r_max` over
`T_ramp`, then hold that rate. Use the same angle-to-accelerometer equations
as the existing simulator only after verifying sign conventions and mounting.
Label it `progressive_tilt_proxy`, not verified mine subsidence: actual
subsidence-to-tilt mapping depends on spatial displacement gradients and node
geometry.

| Parameter | Proposed setting | Basis and limitation |
|---|---|---|
| Tilt sampling interval | Preserve the evaluation's 1-second tilt interval in a first compatible feature path; high-rate vibration remains a separate stream | One-second evaluation timing is documented in `DATASHEET.md:13` and implemented by `ai_engine/evaluation/datasets.py:114-116`. It is not a measured firmware sampling rate. |
| Episode duration `T_episode` | 6, 24, and 72 hours; **assumption grid** | Longer than the current 120-second episode to expose slow onset and persistence. These horizons are design assumptions, not mine access or measured event durations. |
| Onset `t0` | Uniformly select within the first 10%–50% of each simulated episode; **assumption** | Ensures both pre-event and post-onset samples while varying onset. Freeze the distribution before evaluation. |
| Progressive angle rate `r_max` | 0.001, 0.01, and 0.1 degrees/hour; **assumption grid** | No mine tilt-rate recording or site geometry was verified. These levels are only a sensitivity design; they are not a field range or minimum detectable tilt. |
| Slope ramp `T_ramp` | 1, 6, and 24 hours; **assumption grid** | Allows a gradual onset rather than an instantaneous step. No physical calibration is available. |
| Direction of tilt | Use a fixed, recorded direction per simulated site or a predeclared direction distribution; **assumption until site geometry is supplied** | Direction depends on the ground-deformation gradient and mounting; do not infer it from the current `0.7` axis ratio. |
| Tilt/acceleration noise | Use the existing 0.05-degree and 0.02-m/s^2 values only as labeled assumptions, plus a predeclared sensitivity grid | Source code constants are not measured sensor specifications. Avoid fitting them to the AI's observed result. |
| Persistence/recovery labels | Progressive class persists through episode end; transient classes have a labeled return-to-baseline interval | This is the defining class distinction in the proposed protocol, not an assertion that all real ground deformation is irreversible. |

The new generator must carry each parameter, unit, source/assumption flag, seed,
and record identifier in a manifest. Split empirical records by whole blast
sequence and station before extracting overlapping windows to prevent train/test
leakage. Do not mix public source velocity traces with simulated node
acceleration as if they were interchangeable quantities.

## Existing implementation seams

- `simulator/simulator/node.py:109-138` creates a bounded high-vibration
  reading window and a rapid demo tilt drift; it has no waveform envelope or measured sensor
  transfer function.
- `simulator/simulator/scenarios.py` assigns broad demo scenario names but does
  not define a mine-blast waveform or an event class.
- `ai_engine/evaluation/datasets.py:51-58, 217-296` defines a 120-second,
  one-second-step scenario generator with scripted scalar bursts and event
  labels. Keep it as v1; add a v2 generator alongside it.
- `backend/app/processing/features.py:83-131` can be extended in a v2 path
  with signal-envelope, decay, residual tilt, and multi-window slope features.
- `backend/app/intelligence/temporal.py:82-91` currently averages recent
  deviations under the `cumulative_drift` name; a v2 feature must define units,
  integration interval, baseline handling, and reset semantics explicitly.
- `ai_engine/adapter.py:43-65` currently returns anomaly state/score, not an
  event class. Integrate classification through a separately versioned
  interface after the protocol is approved.
